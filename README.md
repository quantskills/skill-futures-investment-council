# Futures Investment Council｜期货投资委员会研究 Skill

English version: [README.en.md](README.en.md)

> 用一套可重复的研究流程，把**期货行情、趋势/动量/波动率、持仓与期限结构、商品基本面**整理成一份“投资委员会式”研究报告：不仅给出当前市场状态，还明确说明**证据、分歧、反方情景、失效条件与数据完整性**。

`skill-futures-investment-council` 面向商品期货、金融期货等期货研究场景。用户不需要先理解项目里的脚本或专家资料；安装 Skill 后，直接用自然语言提出研究问题即可，Agent 会根据任务选择分析、比较或扫描流程。

> **Community Project / 社区项目**：本项目为社区研究工具，不代表 QuantSkills 官方立场，也不代表、模拟或获得文中所引用投资者本人的认可或背书。专家框架仅用于研究视角的结构化归纳。项目不构成投资建议，不提供自动交易，不承诺收益。

---

## 你可以用它做什么？

最常见的是下面 4 类场景。

### 场景 1：研究一个期货品种

当你想知道一个品种现在处于什么市场状态，以及这个判断由哪些证据支持时使用。

你可以直接问：

> 分析一下沪铜期货，重点看趋势、持仓、基差、期限结构和风险。

> 黄金期货现在是什么市场状态？给我一份投资委员会式研究报告。

> 看一下原油最近的趋势是否得到持仓和基本面的确认。

Skill 会按下面的顺序组织研究：

```text
解析期货标的
    ↓
获取行情与可用基本面数据
    ↓
计算确定性量化特征
    ↓
识别市场状态与数据缺口
    ↓
自动选择相关专家研究框架
    ↓
汇总共识 / 分歧 / 反方证据 / 失效条件
    ↓
生成结构化研究报告
```

典型报告会回答：

- 当前综合市场状态偏多、偏空还是混合；
- 均线、MACD、ADX、突破、RSI 是否一致；
- 价格与持仓变化是否相互确认；
- 基差和期限结构是否支持当前趋势；
- 库存、现货或供需数据是否可用；
- 不同研究框架在哪些地方形成共识；
- 哪些证据与主结论冲突；
- 什么变化会使当前判断失效；
- 当前数据完整性和研究置信度如何。

---

### 场景 2：比较多个期货品种

适合回答“两个或多个品种之间，谁的趋势更清晰、证据更完整、风险更突出”。

你可以直接问：

> 比较沪金和沪银，哪个当前趋势更强？主要风险分别是什么？

> 对比沪铜、沪铝和沪锌的市场状态与置信度。

> 比较黄金和原油，不要只看涨跌幅，要看趋势证据和风险条件。

比较流程会分别运行同一套研究框架，再提取：

- 综合市场状态；
- 研究置信度；
- 主要共识；
- 主要风险；
- 数据缺口。

这使不同品种的比较建立在**统一口径**上，而不是只比较单日收益。

---

### 场景 3：扫描当前趋势更强的期货品种

适合从较大的期货池里先做第一轮筛选，再对候选品种深入研究。

你可以直接问：

> 扫描目前趋势最强的商品期货，列出前 10 个。

> 帮我从期货市场里找出趋势证据最完整的品种。

> 扫描一遍期货市场，先给候选列表，不要直接给交易建议。

当前扫描器依据确定性趋势证据评分，主要包括：

- 均线排列；
- ADX 趋势强度；
- 20 / 55 周期突破；
- RSI 动量状态。

扫描是**研究候选排序**，不是买卖信号。建议对候选品种继续运行单品种研究，再查看持仓、基差、期限结构、基本面和风险条件。

---

### 场景 4：解释“为什么结论不能简单变成交易指令”

这是本 Skill 与普通技术指标扫描器区别比较大的地方。

你可以直接问：

> 为什么黄金趋势偏多，但现在不一定适合追涨？

> 沪铜当前有哪些证据支持上涨，又有哪些反方证据？

> 这个偏多判断在什么条件下会失效？

> 为什么几个研究框架对原油的判断不一致？

Skill 会保留冲突，而不是简单多数投票。它会区分：

- **方向证据**：趋势、动量、突破；
- **结构证据**：持仓、基差、期限结构；
- **基本面证据**：现货、库存、供需等；
- **风险证据**：ATR、回撤、过热状态；
- **数据缺口**：哪些维度当前不可用。

最终输出会明确列出**反方情景和失效条件**，避免把“当前偏多”直接等价为“应该买入”。

## 什么样的提示词会触发这个 Skill？

当用户的问题明确涉及**期货市场研究、期货品种比较、趋势扫描、期货结构分析或委员会式研究解释**时适合调用。

典型提示词：

```text
分析一下沪铜期货。

黄金期货现在是什么市场状态？

比较沪金和沪银当前谁的趋势更强。

扫描目前趋势最强的 10 个商品期货。

原油上涨是否得到持仓和期限结构确认？

为什么这个品种趋势偏多但不建议简单追涨？

列出当前判断的反方证据和失效条件。

用投资委员会方式分析螺纹钢，不要只给技术指标。
```

下面这些问题不是本 Skill 的主要用途：

```text
分析某只股票值不值得买。

给我一个确定的期货买入点和仓位。

自动帮我下单。

保证这个策略未来能赚钱。
```

## 最终会得到什么？

单品种研究默认生成一份 Markdown 研究报告，核心结构包括：

1. 结论摘要
2. 市场概览
3. 市场状态（Market Regime）
4. 技术与趋势
5. 期货结构
6. 商品基本面
7. 专家研究视角
8. 共识
9. 分歧
10. 关键失效条件
11. 风险提示
12. 置信度与数据完整性

示例片段：

```text
综合状态：偏多

趋势证据：
- 均线呈多头排列
- MACD bullish
- RSI overbought

期货结构：
- 价格上涨且持仓增加
- 基差当前无可用读数
- 期限结构当前无可用多到期月份快照

共识：
- 当前可验证证据整体偏多

分歧：
- 短线动量存在过热
- 宏观证据暂不足以独立确认方向

失效条件：
- 价格跌回突破区间
- 均线排列转弱
- 持仓不再支持趋势参与
```

这里的 `confidence` 表示**证据质量与一致性**，不是价格上涨/下跌的概率预测。

## Skill 内部是怎么工作的？

用户不需要记住脚本名。Agent 根据用户意图选择内部工作流：

```text
                     用户问题
                        │
        ┌───────────────┼────────────────┐
        │               │                │
        ▼               ▼                ▼
    单品种研究        多品种比较        市场扫描
        │               │                │
        ▼               ▼                ▼
 analyze_futures   compare_futures    screen_futures
        │               │                │
        └───────────────┬┴────────────────┘
                        ▼
             确定性特征 + 数据质量
                        ▼
                自动路由专家框架
                        ▼
      共识 / 分歧 / 反方证据 / 失效条件
```

**scripts 是 Skill 的内部实现，不是用户菜单。**

## 研究证据层级

本项目要求先有数据证据，再做专家解释。默认优先级为：

1. 确定性量化特征；
2. 期货结构数据；
3. 商品现货与基本面数据；
4. 可用宏观数据；
5. 专家研究框架解释。

专家叙事不能覆盖缺失数据，也不能把没有数据支持的观点包装成事实。

### 当前主要量化维度

**趋势**

- MA 20 / 60 / 120 排列
- MACD
- ADX
- 20 / 55 周期突破

**动量**

- RSI
- 多周期 Rate of Change

**波动与风险**

- ATR
- ATR / Close
- 波动率状态
- 回撤

**期货结构**

- 持仓量变化
- 价格 × 持仓组合状态
- 基差（`spot - futures`）
- Contango / Backwardation

**商品基本面**

- 现货价格
- 库存及变化
- 可用时的供需和季节性信息

数据缺失时使用 `unknown` 或降低证据权重，不自动编造。

## “投资委员会”是什么意思？

项目内置多种公开投资研究框架，并按品种和证据可用性自动选择相关视角。

主要分为：

- 趋势类；
- 宏观类；
- 商品基本面类；
- 风险管理类。

一次研究不会机械加载全部专家，也不会简单按人数投票。默认目标是选择少量相关视角，并根据**证据是否可用、是否重复引用同一信号、是否与品种相关**调整权重。

例如：

- 一个商品基本面视角如果没有库存/供需数据，权重应该下降；
- 三个趋势视角都引用同一条均线信号，不应该被当成三份独立证据；
- 至少保留一个风险视角和一个反方情景。

### 关于专家资料的声明

`references/experts/` 中的内容是根据公开资料整理的**研究框架摘要**，用于帮助 Agent 从不同方法论审视同一组市场证据。

它们：

- 不是对真实人物的实时模拟；
- 不代表真实人物当前观点；
- 不代表真实人物对本项目的认可或背书；
- 不能替代数据本身。

## 数据来源

### 默认实时研究

默认配置使用 **PandaData** 获取期货行情，并在可用时使用 **AKShare** 补充现货/基本面数据。

实时环境需要设置：

```text
PANDA_DATA_USERNAME
PANDA_DATA_PASSWORD
```

推荐从示例文件开始：

```bash
cp .env.example .env
```

然后在本地填写凭据。

> 不要把真实 `.env`、账号、密码、API Key 或 Token 提交到 Git 仓库。

如果 PandaData 登录、凭据或网络失败，Skill 会报告实时数据不可用，不会偷偷切换到其他历史 CSV。

### 离线 / Smoke Test

仓库提供合成数据和离线配置，用于验证计算链路是否正常。离线样例不代表任何真实证券，也不用于证明策略收益。

## 安装

要求 Python 3.10+。

### 使用 uv

```bash
uv sync
```

使用 uv 时，后续命令建议通过 `uv run ...` 执行，例如 `uv run futures-investment-council --symbol 沪铜`。

默认实时数据源还需要 PandaData SDK。仓库当前附带对应 wheel 时，可安装：

```bash
uv pip install scripts/vendor/panda_data-0.0.9-py3-none-any.whl
```

### 使用 pip

```bash
python -m pip install .
python -m pip install scripts/vendor/panda_data-0.0.9-py3-none-any.whl
```

可选增强依赖：

```bash
python -m pip install ".[advanced]"
```

## 快速开始

### 1. 分析单一期货

安装后（如果使用 uv，请在命令前加 `uv run`）：

```bash
futures-investment-council --symbol 沪铜
```

也可以使用标准代码：

```bash
futures-investment-council --symbol CU_INDEX
```

指定日期：

```bash
futures-investment-council \
  --symbol 沪铜 \
  --start-date 2025-01-01 \
  --end-date 2026-08-01
```

默认 Markdown 报告会写入用户 `Downloads` 目录（目录不可用时写入用户主目录）。

### 2. 比较多个品种

```bash
python scripts/compare_futures.py \
  --symbols 沪金 沪银
```

输出 JSON：

```bash
python scripts/compare_futures.py \
  --symbols AU_INDEX AG_INDEX \
  --format json \
  --output reports/gold_vs_silver.json
```

### 3. 扫描趋势候选

```bash
python scripts/screen_futures.py --limit 10
```

只扫描指定品种：

```bash
python scripts/screen_futures.py \
  --symbols 沪铜 沪铝 沪锌 沪金 沪银 \
  --limit 5
```

## 对 Reviewer：脚本与场景的对应关系

普通用户不需要关注这一节；本节用于本地调试和验收。

| 场景 | 入口 | 作用 |
|---|---|---|
| 单品种研究 | `futures-investment-council --symbol ...` / `scripts/analyze_futures.py` | 完整委员会研究报告 |
| 多品种比较 | `scripts/compare_futures.py` | 统一口径比较市场状态、置信度、共识与风险 |
| 趋势扫描 | `scripts/screen_futures.py` | 基于趋势证据给候选品种排序 |
| 离线验收 | `scripts/smoke_test.py` | 验证最小完整分析链路 |
| 数据源诊断 | `scripts/measure_spot_price.py` | 调试/测量 AKShare 现货请求，不是用户主入口 |

## 配置

默认研究配置位于：

```text
scripts/skill_futures_investment_council/settings.yaml
```

离线测试配置：

```text
scripts/skill_futures_investment_council/settings/smoke.yaml
```

主要可配置项包括：

- 数据源；
- 研究频率和回看区间；
- MA / MACD / ADX / RSI / Breakout 参数；
- 持仓、基差和期限结构功能；
- 库存、供需、季节性功能；
- 专家路由；
- Markdown / JSON 输出。

如果用户没有明确要求，不建议为了得到更“漂亮”的结论而临时修改指标参数。

## 输出格式

支持：

```text
markdown
json
```

例如：

```bash
futures-investment-council \

  --output reports/crude_oil.json
```

## 已知限制

- 默认实时研究依赖 PandaData 凭据和网络可用性；
- AKShare 接口可能受外部数据源可用性影响；
- 库存、基差、期限结构、供需等字段并非所有品种和时间段都完整；
- 缺失维度会降级为 `unknown`，因此不同报告的数据完整性可能不同；
- 趋势扫描器当前主要是**趋势证据排序**，不是完整基本面评分器；
- 日线指标与委员会式研究适合研究和复盘，不等于可直接执行的实时交易信号；
- 专家框架是方法论视角，不是人物预测模型；
- 任何历史或当前市场状态都不能保证未来表现。

---

## 研究边界与风险声明

本项目只用于**期货市场研究与教育**。

它不会：

- 自动下单；
- 输出保证收益的策略；
- 把委员会共识包装成确定性买卖指令；
- 在数据缺失时编造库存、基差、期限结构、供需或宏观数据；
- 用股票研究逻辑替代期货研究。

本仓库对公开投资研究方法进行结构化归纳，仅用于研究框架参考。**本项目与文中提及的任何投资者或机构均无隶属或合作关系，不代表其官方观点，不验证任何收益声明，也不构成投资建议。**

使用者应自行判断数据质量、交易成本、流动性、保证金、杠杆、滑点、涨跌停、夜盘以及其他期货交易风险。

## 一句话总结

> **Futures Investment Council 不是“让几个名人投票预测涨跌”，而是先计算可验证的期货证据，再用多个研究框架解释证据中的共识、冲突、风险与失效条件。**
